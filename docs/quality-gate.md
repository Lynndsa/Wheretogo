# Quality Gate v0 — Wheretogo

## Выбранное изменение

Pull Request, который добавляет или обновляет документацию проекта (`requirements.md`, `mvp.md`, `layout.md`) и настраивает монорепозиторий (`android/` и `backend/`) с CI-пайплайном. Поскольку это изменение существенных требований и конфигурации сборки, оно является значимым согласно регламенту процесса разработки и требует обязательного независимого review.

| Вопрос | Ответ                                                                                                                                                                   |

## Как результат проверок влияет на слияние

- Статусная проверка сборки в GitHub Actions обязательна: ошибка в сборке или падение тестов блокируют слияние в `master`.
- Зелёный статус пайплайна — необходимое, но не достаточное условие. Для документов или конфигурации сборки автоматика не проверяет логику и полноту, поэтому ключевую роль играет содержательное review.
- Слияние в `master` возможно только после успешного прохождения CI и получения одобрения от независимого ревьюера.

## Ограничения текущих проверок

Сейчас в GitHub Actions настроена автоматическая сборка и базовые тесты с учетом рабочей директории монорепозитория (`working-directory: android`). Полные интеграционные тесты, статический анализ кода (Lint) и расширенные проверки безопасности подключаются по мере развития проекта. Зелёный статус сборки подтверждает техническую корректность структуры, но не заменяет ручную проверку пользовательских сценариев.

## Что проверить перед сдачей

- В настройках репозитория на GitHub включены: защита ветки `master`, запрет прямого push, обязательное использование Pull Request, обязательные статусные проверки (CI Checks) и требование хотя бы одного независимого Approval.
- Триггеры в файле `.github/workflows/ci.yml` настроены корректно (срабатывают при pull request в основные ветки с фильтрацией по путям `android/**` и `backend/**`).

# Спецификация требований 1.0 — Wheretogo

## 1. Основной сценарий в границах MVP

Вход в приложение или гостевой режим → интерактивная карта с точками → выбор маршрута или музея → просмотр подробной информации и контактов → добавление в «Избранное» → построение маршрута и прогулка → отметка о посещении в личном кабинете.

Существенные ошибочные исходы: неверные данные при входе; недоступен backend или внешний API карт/музеев; пустой список локаций; у объекта отсутствуют координаты или описания. При недоступном интернете карта будет загружаться, которая была сохранена в кэше.

## 3. Нефункциональные требования

Числа — **цели**, а не доказанные характеристики.

| ID | Требование | Основание | Приоритет | Критерий и способ проверки |
|---|---|---|---|---|
| NFR-01 | Отклик при загрузке точек на карте | Производительность UI | MVP | Среда: эмулятор + локальный Spring Boot бэкенд, от 50 точек в БД. Измерение: 20 запросов отрисовки. Цель: 95-й процентиль не более **2 с** (согласовать) |
| NFR-02 | Секреты (ключи карт, пароли БД, токены) не попадают в репозиторий и журналы | DoD, development-process §6 | MVP | Поиск по репозиторию (`git grep`), review PR; секреты — только в переменных окружения / GitHub Secrets / `local.properties` |
| NFR-03 | Избранное и профиль защищены JWT-токеном | Ранние ограничения безопасности | MVP  | Запрос к защищенным эндпоинтам бэкенда без токена → отказ (HTTP 401); в БД пароли хранятся в захешированном виде |

## 4. Собственная логика и модуль-кандидат

Собственная логика проекта заключается в фильтрации и объединении данных из внешнего API и локальной базы данных (Room/H2), а также в обработке избранного без дублирования записей (FR-04, FR-05). Объект инженерного эксперимента — сетевой клиент и модуль кэширования локальных данных: можно отдельно тестировать fallback-механизм при недоступности внешнего API.

## 5. Резерв

Не входит в baseline (озвучка маршрутов, возможность создавать личные маршруты, которые видны другим пользователям, личные заметки пользователя к местам).

## 6. Ограничения и допущения

Ограничения: сроки выполнения учебного семестра, доступность учебной среды разработки (Android Studio / IntelliJ IDEA), работа в условиях монорепозитория.

**Допущения** интерактивная карта ускоряет выбор локаций; сохранение в избранное повышает вовлеченность пользователей; локальный кэш снижает нагрузку на внешний API при нестабильной связи.

**Уже доступно / планируется:** Экран входа и гостевой режим, базовая структура монорепозитория с настроенным CI/CD, отображение карты.

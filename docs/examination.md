## 2. Примеры сценариев обработки данных

### Пример 1. Поиск достопримечательности

- **Что проверяет/обрабатывает код:** Android-клиент отправляет запрос к серверной части Spring Boot для получения информации о достопримечательностях.
- **Правило принятия решений:** при успешном ответе сервера приложение обрабатывает полученные данные и отображает доступную информацию о выбранном месте.
- **Что делать при ошибках:** если сервер или внешний API недоступен, приложение должно обработать ошибку и сообщить пользователю о невозможности загрузить данные.

### Пример 2. Динамическая загрузка достопримечательностей на карте

- **Что проверяет/обрабатывает код:** приложение определяет текущее местоположение пользователя и отображает карту с достопримечательностями. При изменении масштаба или области просмотра карты приложение получает координаты видимой области и загружает соответствующие достопримечательности через серверную часть Spring Boot.

- **Правило принятия решений:** набор отображаемых достопримечательностей зависит от текущей области карты и её масштаба. При приближении карты пользователь может увидеть больше подробностей и отдельные объекты, а при отдалении — обзор интересных мест на более широкой территории. При перемещении карты загружаются достопримечательности, соответствующие новой области просмотра.

- **Что делать при ошибках:** если сервер или внешний API недоступен, приложение обрабатывает ошибку загрузки и уведомляет пользователя. Уже отображаемые данные могут оставаться на карте до получения новых результатов, если это предусмотрено реализацией.


Данный сценарий является планируемым и требует реализации и тестирования.

### Пример 3. Создание и проверка маршрута гидом

- **Что проверяет/обрабатывает код:** планируемый модуль создания маршрутов проверяет название, описание и список выбранных точек перед сохранением.
- **Правило принятия решений:** если обязательные поля заполнены корректно, приложение формирует данные маршрута и отправляет запрос на сервер Spring Boot.
- **Что делать при ошибках:** при недоступности сервера приложение должно показать сообщение об ошибке. Сохранение черновика и повторная отправка после восстановления соединения могут быть реализованы дополнительно.

Данный сценарий описывает предполагаемую функциональность.

## 3. Модуль для отдельного наблюдения и тестирования

**Модуль-кандидат: Data / Network Layer (сетевой слой, или сетевой репозиторий).**

| Поле | Содержание |
|---|---|
| Назначение | Обеспечивает взаимодействие Android-клиента с серверной частью Spring Boot и обработку полученных ответов. |
| Как наблюдать | Использовать Logcat в Android Studio для просмотра запросов, ответов и ошибок. Проверять адреса запросов, параметры, структуру JSON и HTTP-статусы. |
| Как измерять | Измерять время выполнения запросов, проверять корректность ответов и обработку сетевых ошибок. |
| Успешный сценарий | Сервер возвращает корректный ответ, данные успешно преобразуются в объекты приложения и отображаются пользователю. |
| Негативный сценарий | Сервер недоступен, возвращает ошибку или некорректные данные. Приложение корректно обрабатывает ситуацию и не завершается аварийно. |
| Инструменты тестирования | Unit-тесты и MockWebServer для имитации ответов сервера, включая успешные ответы и ошибки. |

## 4. Внешние ресурсы

| Ресурс | Назначение |
|---|---|
| Сеть (HTTP/REST API) | Обмен данными между Android-клиентом, сервером Spring Boot и внешними API. |
| Серверная часть Spring Boot | Обработка запросов, получение и подготовка данных для Android-клиента. |
| База данных | Хранение информации о пользователях, настройках, достопримечательностях, избранном и маршрутах в соответствии с реализованной структурой проекта. |
| Android-устройство или эмулятор | Запуск приложения и проверка пользовательских сценариев. |
| MapLibre | Отображение интерактивной карты. Доступность карты зависит от настроенного источника тайлов. |
| Внешние API | Получение информации о достопримечательностях и дополнительных сведений о местах. |
| Локальное хранилище Android | Возможное хранение заранее загруженных данных для последующего доступа без интернета. Требует соответствующей реализации. |

## 5. Критерии успешной проверки

- [ ] Android-клиент корректно взаимодействует с серверной частью.
- [ ] Сетевой слой обрабатывает успешные ответы сервера.
- [ ] Приложение корректно обрабатывает ошибки сети и недоступность сервера.
- [ ] Полученные данные преобразуются и отображаются без ошибок.
- [ ] Отсутствие необязательных данных, например описания или фотографии, не приводит к сбою.
- [ ] Результаты тестирования соответствуют требованиям проекта.

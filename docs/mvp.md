# MVP Wheretogo 0.1

## 1. Цель MVP

Проверить основной пользовательский сценарий: пользователь входит в приложение, просматривает карту, вручную выбирает маршруты, предложенные приложением, открывает избранное и изучает подробную информацию о маршруте.

## 2. Обязательные функции

| ID     | Функция             | Критерий готовности                                                                                                                                                                                                                                                                                                |
|--------|---------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| MVP-01 | Регистрация и вход  | Пользователь может создать аккаунт и войти; ошибки обрабатываются                                                                                                                                                                                                                                                  |
| MVP-02 | Просмотр карты      | Карта загружается из api, корректно отображается информация на карте, есть возможность прокручивать и приближать карту                                                                                                                                                                                             |
| MVP-03 | Просмотр маршрутов  | На карте отображаются популярные или свои маршруты в зависимости от выбранного режима                                                                                                                                                                                                                              | |
| MVP-04 | Загрузка музеев     | Загрузка информации по достопремечательностям из api, при отсутствии информации в api берется информация из базы данных, если же в базе данных нет информации, то музей не отображается на карте                                                                                                                   |
| MVP-05 | Избранное           | В избранном хранятся маршруты и музеи, которые пользователь захотел добавить                                                                                                                                                                                                                                       |
| MVP-06 | Навигация           | Навигация должно работать корректно(при нажатии на кнопку "Регистрация" должно переходить на окно "Регистрация"), переходы должны быть плавными, при нажатии на кнопку "Назад" на устройстве, дожно переходить на предыдущий экран. При необходимости сохранять данные на странице при переходе на другую страницу |
| MVP-07 | Личный кабинет      | В личном кабинете должны отображаться посещеннные маршруты и музеи                                                                                                                                                                                                                                                 |
                                                                                                                                                                       |

## 3. Резерв функций

Следующие функции не блокируют приёмку MVP:


- Загрузка маршрутов - загрузка популярных маршрутов из api (возможно не получиться разместить маршруты на карте).
- Просмотр оффлайн карты (создается резевная копия карты при ее загрузке и при отсутствии интернета загружается резерная копия).
- Возможность создания собственных маршрутов (для гидов, чтобы они могли размещать свои маршруты с информацией о нём).
- Прямо в приложении записываться на маршруты (если он выложен другим человеком), с установленной стоимостью и проведение оплаты в приложении.

## 4. Минимальный результат первой практической

Для первой демонстрации необходимо подготовить репозиторий для проекта, активность с загруженной картой и минимальной навигацией (Главный экран -> Вход -> Регистрация).

## 5. Условия выхода из MVP

MVP считается готовым, когда выполнены критерии MVP-01–MVP-07, приложение проходит сборку и предусмотренные проверки, а известные ограничения зафиксированы в документации.

Функции резерва не должны задерживать завершение обязательного сценария.

## 6. Сценарий
Пользователь заходит в приложение -> выбирает режим просмотра (авторизован или как гость) -> открывает интерактивную карту -> выбирает интересующий маршрут или музей -> изучает подробную информацию и отзывы -> добавляет маршрут/музей в «Избранное» -> прокладывает маршрут на карте и отправляется на прогулку -> отмечает место как посещённое -> посещённый объект сохраняется в личном кабинете в истории поездок

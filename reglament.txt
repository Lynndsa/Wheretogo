2. ПОСТАНОВКА ЗАДАЧ
Все задачи создаются через GitHub Issues.
Каждая задача должна содержать:
  — заголовок
  — описание (что нужно сделать)
  — исполнителя (Assignee)

Задачи назначаются друг на друга через поле Assignees.
Прямое общение по задачам — в комментариях к Issue.

3. ВЕТВЛЕНИЕ
Главная ветка: master (защищена, прямой push запрещён).
Для каждой задачи создаётся отдельная ветка с названием задачи

4. PULL REQUEST И РЕВЬЮ
Любое изменение попадает в master только через Pull Request.
Правила:
  — PR создаётся из ветки задачи в master
  — минимум 1 approve от другого участника команды
  — self-merge и self-approve запрещены

5. CI
На каждый push и Pull Request запускается GitHub Actions.
Workflow: .github/workflows/ci.yml
Этапы: restore → build
Красный CI = merge запрещён.
Зелёный CI = PR готов к merge (при наличии approve).
